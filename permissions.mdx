This page is about the permissions **Quark** needs. For the permissions a **member** needs to run a command, see the [command list](/commands/list).

## The short version

<Tip>Giving Quark **Administrator** avoids every problem on this page, and new log types work as soon as they are released. The invite link asks for it by default.</Tip>

If you do not want to grant Administrator, Quark needs at least:

1. **View Audit Log** on its role, server-wide.
2. **View Channel**, **Manage Webhooks** and **Embed Links** in every log channel.
3. **View Channel** in every channel you want logged.

The rest of this page lists what each permission is for, so you can decide what to leave out.

To check your server, run `/troubleshoot`. It reports every permission Quark is missing in each log channel and what that costs you.

## What the invite link asks for

| Permission | Why |
| --- | --- |
| Administrator | Covers everything below, in every channel. A join log only says "joined without an invite" when Quark is an Administrator |
| View Audit Log | Most moderation, role, channel and server logs are built from the audit log |
| Manage Server | Shows which invite a new member used, and receives AutoMod rule changes |
| Manage Webhooks | Logs are delivered through a webhook Quark creates in each log channel |
| View Channels | Sees the channels it logs and the channels it posts in |
| Send Messages, Send Messages in Threads | Posts logs when no webhook is available, and posts tags |
| Embed Links | Standard logs are embeds |
| Attach Files | Re-posts deleted files |
| Read Message History | Reads the message a reaction log refers to, and reads messages for `/purge` |
| Use External Emojis | Shows the icon in each log's title |
| Kick Members, Ban Members, Timeout Members | For `/kick`, `/ban`, `/unban`, `/mute`, `/unmute`, the Ban button on join logs, and [automation](/dashboard/automations) rules and [action buttons](/dashboard/formats#action-buttons) that time out, kick or ban |
| Manage Messages | For `/purge`, and automation rules and action buttons that delete a message |
| Manage Roles | For automation rules and action buttons that give or take a role |

One permission Quark can use is not in the invite link and only comes with Administrator: **Manage Channels**. If you remove Administrator, add Manage Channels yourself if you want invite logs, or want Quark to create #quark-logs during setup.

The invite link has not always asked for Manage Messages and Manage Roles. A server keeps the permissions it gave Quark when it was added, so if Quark does not have Administrator in your server, grant those two to its role when you need them.

## In each log channel

Quark needs these in every channel it sends logs to.

| Permission | Without it |
| --- | --- |
| View Channel | Nothing can be delivered to the channel |
| Manage Webhooks | Quark cannot create or reuse its webhook. Logs only arrive if Quark can post them itself, which needs Send Messages |
| Embed Links | Discord accepts the log and shows an empty message |
| Send Messages | Logs still arrive through the webhook, but stop if the webhook is lost or was never created |
| Attach Files | Deleted files and bulk-delete files cannot be posted, and images cannot be added to a modlog that Quark posted itself and not through its webhook. Other logs are unaffected |
| Use External Emojis | Log titles show raw emoji names instead of icons |
| Read Message History | Edit Reason cannot open the modlog it is editing |

## Server-wide

### View Audit Log

Discord only tells a bot who did something through the audit log. Without **View Audit Log** these log types are never sent:

- **Modlogs**: Ban, Unban, Kick, Timeout, Timeout Removed
- **Roles**: Role Create, Delete and Update, Role Permissions Updated, Role Icon Update
- **Channels**: Channel Create, Delete and Update, the three Channel Permissions logs, all webhook logs, Channel Followed, Unfollowed and Followed Channel Updated
- **Server and members**: Server Modified, Server Icon Update, Server Banner Update, Nickname Update, Role Given, Role Taken, Members Pruned, Bot Added
- **Actions**: Invite Delete, and the emoji, sticker and event logs
- **Voice**: Moved, Disconnected, Voice Channel Status Updated, Stage Started, Ended and Updated
- **Messages**: Delete Multiple Messages, Thread Delete, Thread Updated, Thread Closed, Reopened, Locked and Unlocked, Auto Moderation Message Blocked

The [log types table](/logs/types) marks each of these.

Other logs are still sent, but lose detail:

| Log | Without View Audit Log |
| --- | --- |
| Message deleted | No "Deleted by" |
| Moved, Disconnected | Shown as an ordinary Voice Channel Change or Voice Channel Leave |
| Server Mute, Deafen, Unmute, Undeafen | No moderator. Showing the moderator also needs Quark Pro |
| Bot Removed | No record of who removed the bot |
| Message Pinned, Message Unpinned | No record of who pinned or unpinned the message, and only sent for a message Quark had stored |
| Soundboard and AutoMod rule logs | No record of who made the change |

<Warning>If Quark cannot tell who did something, the ignore rules for who did it cannot apply to that log.</Warning>

### Other server-wide permissions

| Permission | Needed for |
| --- | --- |
| Manage Server | Showing which invite a new member used, and receiving AutoMod rule logs |
| Manage Channels | Invite Create logs. Discord only sends invite events to bots with Manage Channels in that channel |
| Manage Webhooks | Webhook Modified, Webhook Avatar Updated, Channel Followed and Followed Channel Updated |
| Read Message History | Reaction Removed logs |

## In the channels you want logged

Quark needs **View Channel** in a channel to log the messages in it. To keep a private channel out of your logs, remove View Channel for Quark in that channel, or add the channel to the [ignore rules](/logs/options#ignore-rules).

## For commands

Quark's own permissions for each command. The member running the command needs their own permissions too. See the [command list](/commands/list).

| Command | Quark needs |
| --- | --- |
| `/ban`, `/unban`, the Ban button on join logs | Ban Members. For `/ban`, Quark's highest role must also be above the member's highest role |
| `/kick` | Kick Members, and a role above the member's highest role |
| `/mute`, `/unmute` | Timeout Members. Members with Administrator and the server owner cannot be timed out |
| `/purge` | View Channel, Read Message History and Manage Messages |
| `/tags send` | Send Messages and Embed Links in the channel |
| Edit Reason on a modlog | View Channel and Read Message History in the modlog channel. To add images to a modlog that Quark posted itself and not through its webhook, Attach Files there too |
| Everything else | Nothing extra |

## For automations

Quark's own permissions for each action an [automation](/dashboard/automations) rule can take. The person saving the rule needs their own too, and has to keep them for the rule to go on acting. See [who a rule acts for](/dashboard/automations#who-a-rule-acts-for).

| Action | Quark needs |
| --- | --- |
| Tell a channel | View Channel and Send Messages in that channel |
| Add a notice to the log, Don't send this log | Nothing extra |
| Time someone out | Timeout Members |
| Kick someone | Kick Members |
| Ban someone | Ban Members |
| Delete the message | Manage Messages in the message's channel |
| Give or take a role | Manage Roles, and a highest role above the role it gives or takes |
| Send someone a DM | Nothing extra |

For a timeout, kick, ban, role change or message delete, Quark's highest role must also be above the highest role of the member, or of the message's author. The server owner cannot be acted on.

If Quark is missing a permission, that step of the rule is skipped. The rule's row on the dashboard says why, and Quark posts a **Rule Action** log about it, at most once an hour for each reason. The same happens when the person who last changed the rule has lost theirs.
